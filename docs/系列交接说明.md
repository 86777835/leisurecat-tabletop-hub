## 技术约定（所有站一致）

- Cloudflare Workers + 静态资源，纯原生 JS，**没有构建步骤、没有框架**。
- 多人房间：Durable Objects——`Room`（每个房间一个，WebSocket 同步）、`Lobby`（首页房间列表）、`Archive`（往期对局）。
- `public/logic.js` 是前后端共用的规则逻辑，服务端 `reduce()` 权威校验。
- 前端 `public/app.js` 用 DOM `morph()` 增量渲染。会被 morph 抹掉的界面状态（展开/收起、表单草稿）放在 `ui` 对象里。
- 隐藏信息类游戏（惨剧轮回，以及在做的血染、阿瓦隆）：隐藏信息**在服务端按连接身份过滤**，不能只靠前端隐藏，必须有测试证明不泄露。
- 部署：在子项目目录里运行 `wrangler deploy`（Wrangler 已登录用户账号）。
- Rate limit 的 `namespace_id` 在账号内必须唯一。已用：1001 pgh、1101 bham、1002 odin、1013 tl、1021 / 1031（方舟、沙丘，项目已停）、1041 arnak、1051 / 1052 首页、1061 botc、1071 avalon。

## 规则助手（每个站右下角的“规则”悬浮窗）

- `/api/chat`：只依据本站的讲解稿（`tools/讲解稿.md`）和常见问题（`tools/faq.json`）回答，资料里没有的不能编。
- 模型顺序：DeepSeek V4.1 Flash（`deepseek-flash`）→ Workers AI 上的 `@cf/qwen/qwen3.8-27b` → DeepSeek V4 Pro（`deepseek-v4-pro`）。这个顺序是用户批准过的兜底方案。
- 超时与切换：每个模型 9 秒内必须开始回答；回答中途停顿超过 8 秒，换下一个模型从头回答。
- 每小时 cron 检查一次 DeepSeek，不通时把结果写进 KV，接下来一小时先用 Qwen。
- 回答下方**不显示**是哪个模型答的（用户明确要求）。
- DeepSeek 密钥是各 Worker 的 secret，**由用户自己设置**：`wrangler secret put DEEPSEEK_API_KEY --name <worker 名>`。不要向用户要密钥，也不要替用户输入。
- Workers AI 免费额度是整个账号共用的（每天约 1 万 neurons），用完后 Qwen 那一级会失败。

## 总入口 `桌游助手首页/`

- `public/index.html`：3D 转盘。游戏盒用官方盒封面做成立体盒子，左右滑动选择，点击后“放大 + 虚化”进入对应的站。
- `public/games.json`：游戏库，共 24 款，数据来自 BGG。带 `url` 字段的是有助手的站，会出现在转盘上；其他游戏只出现在“帮我选游戏”里。新站上线后在这里加 `url`，并把 `box`（真实尺寸 cm）、封面 `img/box-<key>.jpg` 补齐。
- `public/picker.js`：“帮我选游戏”，支持按条件打推荐指数、随机、问 AI，结果用抽盲盒动画揭晓。
- `public/order.js`：“定先后手”，有手指轮盘（多点触控）和袋子抽签两种。
- `public/reviews.js` 与 `src/worker.js` 里的 `/api/reviews`：统一的玩家评价接口，存在 `Reviews` Durable Object（SQLite）里，允许 `*.leisurecat.cloud` 跨域访问。
  - 提交：`POST /api/reviews`，body 为 `{ game, stars: 1-5, name, text, room }`。同一 game + room + name 再次提交会覆盖上一条。
  - 查询：`GET /api/reviews?game=<key>`
  - 汇总：`GET /api/reviews`
- `/api/pick`：AI 选游戏接口。**首页 Worker 还没有设 DeepSeek 密钥**，要等用户设置。
- `海报/`：总入口海报，带二维码。源文件在 `海报/源文件/poster.html`，用 Playwright 截图导出。
- 微信分享卡片：页面里已有 `og:` 标签和隐藏缩略图，但微信要显示自定义卡片，基本需要已认证的公众号、JS-SDK，以及已备案的域名。目前没有做，用海报加二维码代替。

## 用户偏好与规矩

- 中文界面，文案简洁，手机优先。多数人在**微信内置浏览器**里用，跨境网络不稳定，要考虑断线和慢网。
- 规则必须依据官方规则书、FAQ 和勘误，不确定就写明来源，不能编。
- **兜底逻辑默认禁止**：主路径失败时给出明确报错。要加兜底，先说明原因并征得用户同意。
- 改动要外科手术式：只动必须动的地方，沿用现有风格。
- 线下用实物更方便的环节留在线下，只把繁琐、易错、需要记录的环节做成线上功能。新站先做社区调研，出一份“做 / 不做”清单给用户确认后再开发。
- 版权：
  - 首页和封面用**官方游戏盒封面原图**，用户明确说过不要 AI 重绘的官方封面。
  - 其他插画用 Codex CLI 生成原创图。
  - 规则说明、常见问题、剧本说明都用自己的话写，不大段照搬原文。
- 只做线下对局辅助，**不做能在线直接玩游戏的数字版**。
- 部署新站、绑定域名、新建 GitHub 仓库之前，先问用户。
