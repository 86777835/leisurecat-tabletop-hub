## 用户已确认的方案

1. **第一步：判断是哪款游戏（前端，不用 AI）**
   - 用游戏名和常见别名、特有术语做关键词匹配。比如：“匹兹堡”→pgh；“伯明翰”→bham；“奥丁”“维京”→odin；“惨剧”“剧作家”“轮回”→tl；“阿纳克”→arnak；“血染”“说书人”“魔典”→botc；“阿瓦隆”“梅林”“刺客”→avalon；“沙丘”“起义”“沙虫”→dune（再看是基础版还是起义）。别名表请从各站讲解稿和 FAQ 里挑**只属于这一款**的词，跨游戏通用的词（“回合”“计分”“领袖”“角色”“工业革命”“运河”……）不能单独决定游戏。
   - 唯一命中：直接用这款游戏回答。
   - 没命中或命中多款：显示一排游戏按钮让用户点选，只列候选（命中多款时只列命中的；没命中时列全部有助手的游戏），**默认选中转盘当前居中的那款**（如果它有助手）。用户点选后再发送。
   - 同一对话里用户已经选过游戏，后续追问沿用这款，除非新问题明确命中另一款；换游戏时清空上下文，并在对话里显示一行“已切换到 XX”。
   - 别名表和匹配函数写成纯函数，放在独立文件里，方便单测。
2. **第二步：交给该站的规则助手**
   - 新增 `POST /api/ask`，body 为 `{ game, messages }`。`game` 必须是 `games.json` 里带 `url` 的 key，否则 400，并给出明确的中文报错。
   - 服务端通过 **Service Bindings** 把 `{ messages }` 原样转发到对应站的 `/api/chat`，把流式响应原样回给前端。各站已有 DeepSeek → Qwen → V4 Pro 兜底、超时切换、不显示模型名，总入口**不新增任何模型调用，也不需要 DeepSeek 密钥**。
   - 转发时带上原请求的 `cf-connecting-ip`，让各站按访客 IP 限流照常生效。各站返回的错误（429、503 等）原样透传。
   - 绑定表（Worker 名以各站 `wrangler.jsonc` 为准，下面已核对）：

     | game key | Worker |
     |---|---|
     | pgh | brass-pittsburgh-room |
     | bham | brass-birmingham-room |
     | odin | feast-for-odin-room |
     | tl | tragedy-looper-helper |
     | arnak | lost-ruins-of-arnak-room |
     | botc | botc-helper |
     | avalon | avalon-helper |
     | dune-imperium、dune-uprising | dune-imperium-helper（同一个站）|

   - 沙丘基础版和起义规则差别大：转发前在用户最后一条问题前面加上“（版本：基础版）”或“（版本：起义）”，让沙丘站的助手知道版本。其他游戏不加任何前缀。
3. **没有助手站的游戏**（`games.json` 里没有 `url` 的 17 款）：如果问题明确命中这些游戏的名字，直接回复“这款还没有收录规则资料”，不调用任何接口，不编答案。不用为它们准备别名表，只用游戏中英文名匹配。
4. **界面**
   - 首页右下角加悬浮按钮“问答”，样式与各站的“规则”按钮一致，但不要挡住转盘底部的文字和评价胶囊；手机 390 宽和 320 宽都要检查。
   - 面板标题“桌游规则问答”，欢迎语说明“问任何已收录游戏的规则”，下面放 3–4 个示例问题（来自不同游戏）。
   - 每条回答上方标注是哪款游戏（中文名），回答下方放“进入 XX 助手 ›”链接（沙丘按版本链到 `?v=base` / `?v=uprising`）。
   - 回答下面**不显示模型名**。
   - 流式解析、`reset`（清空已显示的部分回答）、`error`、30 秒等待上限、断网提示，照匹兹堡 `chat.js` 的做法。
   - 打开问答面板时不要影响转盘的滑动、定先后手和帮我选游戏。
